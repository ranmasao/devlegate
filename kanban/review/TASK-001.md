## Milestone

Devlegate 0.5.5 packaging and self-hosting hardening.

## Goal

Replace the placeholder Debian package maintainer identity with the real Devlegate
maintainer identity and lock the production package metadata down with regression
coverage.

## Context

The current Debian package generated by `tools/package_deb.py` contains:

```text
Maintainer: Devlegate maintainers <maintainers@devlegate.invalid>
```

This is a placeholder and is not appropriate for a real distributable package.
The project maintainer identity is:

```text
Daniil Romanov <romanov.at.bg@gmail.com>
```

Keep this task narrowly scoped to Debian package metadata and its validation/tests.
Do not change runtime behavior, dependency policy, standalone layout, or the
prohibition on Debian maintainer scripts.

Relevant project documentation includes `docs/DISTRIBUTION.md` and
`docs/RELEASE_PACKAGING.md`.

## Required behavior

- Debian packages produced by the supported packaging path identify the maintainer
  as `Daniil Romanov <romanov.at.bg@gmail.com>`.
- Production Debian metadata must not contain the
  `maintainers@devlegate.invalid` placeholder.
- The existing dependency-free package contract remains unchanged.
- The package must continue to contain no Debian maintainer scripts.
- The change must be covered by a regression test that exercises or inspects the
  production Debian packaging metadata rather than merely changing a test fixture.

## Acceptance criteria

- A newly built Devlegate Debian package reports exactly
  `Maintainer: Daniil Romanov <romanov.at.bg@gmail.com>` through
  `dpkg-deb --info` or equivalent package-field inspection.
- No production Debian packaging code emits `maintainers@devlegate.invalid`.
- Existing Debian package validation still passes without adding runtime
  dependencies or maintainer scripts.
- Relevant focused tests pass.
- The full project test and lint checks remain green.

## Required regressions

- Given a Debian package produced through the production package builder, when its
  control fields are inspected, then `Maintainer` equals
  `Daniil Romanov <romanov.at.bg@gmail.com>`.
- Given the production Debian packaging path, when package metadata is generated,
  then it contains no `devlegate.invalid` maintainer address.
- Given the corrected maintainer metadata, when the existing Debian validator runs,
  then the package remains accepted as dependency-free and without maintainer
  scripts.
