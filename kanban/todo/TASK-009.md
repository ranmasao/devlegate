## Milestone

Devlegate 0.5.5 test and coverage hygiene.

## Goal

Keep Devlegate coverage metrics scoped to Devlegate-owned code by excluding the
vendored NanoYAML submodule from coverage collection/reporting.

## Context

`./dev coverage` currently uses:

```toml
[tool.coverage.run]
branch = true
source_pkgs = ["devlegate"]
```

Because NanoYAML is vendored under `src/devlegate/_vendor/nanoyaml`, coverage.py
counts it as part of the Devlegate package. Current reports therefore include
`src/devlegate/_vendor/nanoyaml/__init__.py` (about 68% coverage and 61 missing
branches), which distorts Devlegate totals and per-module debt.

Devlegate pytest discovery already targets `tests/`; this task is about coverage
scope, not suppressing Devlegate tests or modifying NanoYAML's own upstream test
policy.

## Required behavior

- Devlegate coverage collection/reporting excludes
  `src/devlegate/_vendor/nanoyaml/**` and other code under the project vendor
  namespace as appropriate.
- Vendored code does not contribute to Devlegate total statement or branch
  coverage.
- Vendored modules are absent from `coverage report` and `coverage.json`
  generated by `./dev coverage`.
- Devlegate-owned modules remain measured with branch coverage.
- The exclusion is configured centrally in coverage configuration rather than
  post-processing one output format.
- No NanoYAML source or upstream test behavior is modified.

## Acceptance criteria

- Running `./dev coverage` produces a report/JSON with no
  `src/devlegate/_vendor/nanoyaml` entries.
- The total coverage reflects only Devlegate-owned measured code.
- Branch coverage remains enabled for Devlegate.
- CI badge generation continues to consume the corrected total without special-case
  filtering.
- Full tests and lint remain green.

## Required regressions

- Given a coverage run that imports vendored NanoYAML, when reports are generated,
  then the vendor path is absent from measured files/totals.
- Given a Devlegate-owned module, when coverage runs, then it remains present with
  branch metrics.
