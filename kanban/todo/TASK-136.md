## Problem and purpose
A failed TASK-134 OpenCode worker produced a single completed `apply_patch` tool event of roughly 1.88 MB, with about 1.85 MB in `state.metadata.diagnostics` (4,970 basedpyright diagnostics across five files). Devlegate correctly refused a JSONL event larger than its 1 MiB bounded transport limit. OpenCode attaches an accumulated multi-file LSP diagnostic snapshot to edit-tool results; the useful textual tool output was only about 12.5 KB. Keep automatic LSP assistance for the coding agent, but prevent redundant diagnostic metadata from exhausting the Devlegate transport.

This is a narrow 0.5.7 operational unblock before resuming deferred TASK-134. It is not the post-0.6 TASK-012 OpenCode-adapter extraction.

## Implementation contract
1. Supply a small, separately packaged static JavaScript (or plain ESM) OpenCode plugin and materialize/register it in the temporary per-worker OpenCode configuration created by `WorkerSupervisor`. Use the supported `tool.execute.after` hook for `apply_patch`, `edit`, and `write`. Verify the installed OpenCode version actually loads the plugin before relying on it. Preserve LSP activation and the existing `devlegate_report.ts` generation unchanged.
2. Change only `metadata.diagnostics` of those edit-tool results. Preserve `output` (including all LSP feedback visible to the agent), title, input, tool identity, diff, files, and all unrelated metadata. Never alter the semantic `devlegate_report` tool/egress validation. No automatic lint/typecheck substitutions or disabling LSP.
3. Limit diagnostic metadata to the files actually touched by the call, where identities can be established from reliable tool metadata/arguments. Handle multi-file patches, deletion and moves deliberately. Enforce an **absolute 64 KiB UTF-8 serialized budget** for the resulting `metadata.diagnostics` regardless of which files were touched, how many diagnostics exist, or the size of any one diagnostic message. Retain errors (severity 1) ahead of warnings, with stable, deterministic ordering; report truncation via a small bounded marker without injecting synthetic LSP diagnostics. Preserve other metadata fields. When touched-file identification is ambiguous, do not retain the unbounded global diagnostic map; use a bounded conservative result rather than guessing paths.
4. No Node/npm/TypeScript build tooling or third-party modules added to the Devlegate project/runtime; the plugin executes in the existing OpenCode environment using JavaScript built-ins only. Python runtime remains **stdlib-only**; use `importlib.resources` or an equally small stdlib resource-materialization mechanism. Ensure the plugin resource ships in wheel and sdist and works after real installation. Avoid altering the embedded `devlegate_report.ts` source in this ticket; TASK-012 owns that eventual cleanup.
5. Retain Devlegate's independent bounded/fail-closed JSONL transport checks; do not silently ignore malformed or oversized events and do not increase the size threshold merely to hide the incident. If the hook cannot prevent an oversized intermediate or final JSONL event in the installed OpenCode version, report a concrete blocker and `incomplete`, not a falsely successful fix.

## Compact synthetic tests — mandatory
- **No captured JSON/diagnostic fixture, session export, megabyte test artifact, or vendored LSP dataset.** Generate all large inputs in memory with a **very compact deterministic Python-stdlib-only generator** (target at most 30 nonblank, noncomment lines; no helper framework, third-party data generator, npm package or dependency). Using existing pytest as the test runner is fine; the generator itself must use only Python stdlib.
- Synthesize the observed shape: roughly 5,000 diagnostics over five paths, both severity 1 and 2, with the input JSON greater than 1 MiB; assert that a two-file patch retains only relevant diagnostics and the resulting diagnostic map is at most 65,536 UTF-8 bytes. Also test a multi-file patch including all diagnostic files, a single extremely long message, Unicode byte accounting, empty/malformed metadata, unknown paths, moves/deletions, and preservation of the agent-visible output and unrelated metadata.
- Test exact plugin packaging, configuration, loading and mutation semantics. In a focused integration check with **real installed OpenCode** and `opencode run --format json`, confirm that a completed `tool_use` event is already filtered before Devlegate receives it and that no earlier emitted event includes the unfiltered giant metadata. Verify LSP feedback is still visible to the agent. Do not equate isolated JavaScript unit-test success with this end-to-end proof.
- Targeted pytest/Ruff and configured exact-commit CI, with concise measured before/after serialized byte counts and a demonstration that the prior 1 MiB incident no longer causes a transport failure.

## Boundaries and acceptance
No generic plugin framework, migrations, OpenCode fork, broad worker-supervisor refactor, mass source reformatting, or unrelated LSP/typing remediation. Preserve process ownership, worker identity, shutdown, WAL/replay, and fail-closed egress semantics. Do not modify live TASK-134 resources or its existing checkpoint. Accept only after a bounded diagnostic-metadata result, unchanged agent-visible LSP behavior, successful packaging, and verified real JSONL boundary.
