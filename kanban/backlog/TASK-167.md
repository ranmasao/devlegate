## Milestone

Deferred design after L/C/O and ordinary continuation policy are settled. Backlog only; schedule only when concrete residual operator friction justifies it.

## Goal

Determine whether a small shared operator presentation can reduce genuine remaining exceptional repair friction without introducing another authority or recovery state machine.

## Context

The older repair design assumed routine reconcile auto/update-base/resume, old recover, and historical adoption. TASK-201/202 removed routine stage commands; Phase II L3 proposes removing obsolete SHA-based workspace repair. Prior review co-publication issue and other historical incidents are motivating evidence, not proof of current failure. TASK-085 owns residual taxonomy and diagnosis.

## Required behavior

- Inventory actual current exceptional operations, actionable blockers, their exact scope, required evidence, authority, risks and truthful outcomes. Normal automatic advancement needs no additional UX.
- Assess whether existing status/inspect and exact explicit commands suffice. If a shared presentation is justified, propose bounded discovery/preview, exact approval and delegation to existing owner operations with stale rejection; default cancel. Distinguish discard/reset/drop/abandonment and privilege; no generic mutation permission.
- Do not require devlegate repair as an outcome; no new backend, WAL/receipt family, historical adoption, synthetic authority, arbitrary Git repair, broad provenance exception or offline second owner. Same UID/TTY is not human authentication. Preserve independently proved present-time authority and distinct operation semantics.
- Provide examples from actual residual cases and smallest operational implementation slice only if benefit demonstrated.

## Acceptance criteria

Evidence-backed decision to retain current commands or implement a narrow presentation, with distinct authorization and proof conditions and no duplicated backend. No production changes, live resource effects or unsupported claims.

## Required regressions

For any recommended presentation specify precise current blocked case, multiple/no candidates, stale approval, cancellation, uncertain outcome and refusal, including no mutation from reads; existing command contracts remain intact.
