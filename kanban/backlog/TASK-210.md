## Milestone

Devlegate 0.5.8 architecture hardening after the three-phase audit. Backlog until explicitly scheduled. Independent vertical substitution; do not introduce dependencies merely because tickets share an audit theme.

## Goal

Eliminate the historical unbound workspace repair route that can reconstruct Git resources without establishing modern generation authority.

## Context

Phase II L3: the old recover command, operator_recovery admission/receipt/replay and path/ref/SHA repair do not establish contemporary generation identity. A seemingly repaired workspace can still be refused at worker admission. Current bound workspace preparation/repair, exceptional reconciliation and abandonment-recover are distinct.

## Required behavior

- Inventory CLI, IPC, fingerprints/receipts, owner dispatch, startup replay, validators, help/docs and internal callers. If no independently necessary modern backend uses recover, remove the verb and all live operator_recovery routes. If a current required backend exists, preserve only that backend and remove historical unbound authority; explain exact caller.
- Unsupported legacy state/commands must refuse before effects and cannot leave a falsely accepted receipt. No new repair command or generic historical adoption.
- Preserve current bound prelaunch repair, ordinary run/retry/reset, exact exceptional reconciliation and abandonment-recover, and historical settled evidence. Do not create generation identity from path/ref/SHA matching.
- Remove superseded tests, adapt genuinely modern fixtures, preserve useful diagnostic refusal.

## Acceptance criteria

Current workflow works without historical SHA repair. No live unbound repair backend or dangling admitted/replay path; public help/IPC truthful. Any retained command is justified by an identified current bound requirement.

## Required regressions

1. Removed CLI/IPC command or obsolete request shape fails closed; no worktree/ref/state mutation or accepted receipt.
2. Old operator_recovery state is not replayed as authority.
3. Exact bound prelaunch repair, launch/report/reset, exceptional reconcile and abandonment-recover retain their behavior. Preserve historical evidence.

## Operational end state and upgrade

The integrated checkpoint must be usable for subsequent self-hosted development without any later ticket. Preserve all unaffected live workflows. Specify the affected active-state/IPC/evidence contracts, the safe quiescent installation boundary, and exact readiness checks. Preserve immutable reports, reviews, pins and necessary independent authority/effect proofs. No production migration, synthetic evidence or mixed-version protocol. If an actual stopped local installation requires conversion of proven state, describe a narrowly scoped one-shot untracked procedure with exact preconditions, backup/dry-run and validation; never invent authority or erase uncertain effects. Focused regressions, Ruff, diff check and exact-checkpoint hosted CI are mandatory.

No eligible pending legacy operator recovery at upgrade.
