## Milestone

Post-0.5.8 architectural simplification; backlog only. Re-evaluate against the planned independent historical/architectural audit and its resulting backlog before scheduling. This is a substantial architecture item, not a short timeout fix; refine or decompose it after the audit if needed.

## Goal

Serve ordinary read-only operator observations independently of the serial mutation-owner loop while retaining exactly one authority for all runtime, Git and workspace mutations. Eliminate unnecessary owner polling, admission and timing coupling for reads rather than accumulate another observation framework.

## Context

TASK-194 made inspection available while a worker is active by admitting read-only operations into owner safe points. At integrated product cafb5e5a87d5d7e62a1877267f70da0777d10bce, runtime.py sets OBSERVATION_WAIT_SECONDS=1.75 (default IPC response timeout 2s), WORKER_OBSERVATION_SECONDS=0.75 and OPERATOR_ADMISSION_TIMEOUT=1.0. _observe_operator_command executes synchronously in the owner loop during supervision, so an expensive observation competes with reset polling. On 2026-11-27 01:26 local time, shortly after successful FRESH admission of reopened TASK-204, the real operator's first devlegate inspect ticket TASK-204 returned "devlegate: service error: read-only observation time budget expired". An immediate repeat returned correct committed ticket, control 8b1a04ee8dcd6c72cdab234383a779c27e018d3a and history. Exact expensive suboperation and whether TASK-205 contributed are unproven. The existing timeout is a symptom of shared execution responsibility, not evidence that the read needs stronger ownership.

Single writer does not mean single reader. Committed Git objects are already immutable; status already uses published runtime snapshots; live worktrees are not immutable and worker changes cannot be excluded by merely serializing owner observations. TASK-195/196 provide a shared committed graph projection/cache. Coordinate with TASK-165/168/181 and the independent audit rather than duplicate their inventories. UX-004 default rendering is a separate concern.

## Required behavior

- Classify actual read-only IPC consumers and evidence by required consistency: committed Git evidence pinned to one explicit control/product revision; safely published immutable runtime snapshots; live local observations with honest time/generation attribution and unavailable/unproven states. Include inspect ticket/execution/prompt/service/workspace, workspace ls and prune preview, status/candidate views and any related observer paths. Establish the weakest sufficient read guarantees separately from mutation-time proofs.
- Ordinary committed ticket and execution inspection must not need the mutation-owner thread or block worker supervision. Capture a coherent published identity with minimal synchronization; perform expensive read-only Git history, blobs, projection and response construction outside that critical section. A newer control revision may be published during a request; a correctly attributed older immutable snapshot is valid, not a reason for unbounded retry. Keep exact report/review/prompt attribution and privacy. Do not require live workspace identity to return independently available committed evidence.
- Reuse existing IPC handling, immutable projections/snapshots and read-only Git capabilities where sufficient. Make shared cache publication/thread access safe and bounded; do not expose mutable owner state to readers. Prefer eliminating owner observation queue/safe-point machinery when no longer required. Do not introduce a second mutation owner, generic async framework, new database, durable read receipts or additional transaction FSM. No global lock around expensive reads. Design residual live observations deliberately; only use short owner snapshot capture if indispensable, do not pretend live observations are atomic. Respect Git object retention, local resource identity and races with ref/worktree removal without manufacturing evidence.
- Preserve sole-owner mutation serialization, reset/stop/retry/recovery admission and all mutation-boundary revalidation; read results do not authorize action. Preserve IPC authentication and existing machine schemas/semantics where sufficient. Read-only operation must not run hooks/filters, fetch, refresh index, mutate refs, SQLite or resources. Audit passive authority observations (including flock-based readiness probes if relevant); readers must not obstruct owner acquisition merely by observing it. Do not weaken legitimate shared exclusion for operations that actually need it.
- Separate transport/connect, request execution, admission and critical-section budgets; choose defensible bounded query/cancellation/concurrency policy independent of reset polling. Avoid globally increasing timeouts as a substitute for decoupling. Bound subprocesses/output/concurrent work; cancellation and shutdown must not interrupt worker or leak read jobs. No fixed numerical performance target without measurements.
- Demonstrate substitutive simplification: before/after call graph, owner queue/poll/safe-point paths removed or retained with reason, actual Git calls and latency under idle/live worker, concurrent reads and control advancement, mutation responsiveness. Preserve required guarantees, not historical implementations. Do not turn this into unrelated CLI presentation or broad runtime decomposition. No runtime-data migration or real-host mutation.

## Acceptance criteria

A normal inspect ticket and exact committed execution query are served independently of worker supervision and mutation admission, returning internally coherent revision-attributed evidence. Slow reads do not consume owner supervision time or delay reset/stop beyond normal mutation constraints; local observation limitations remain explicit. Existing mutation authority and evidence guarantees are preserved. Changes simplify the real architecture and remove superseded paths; any remaining owner-bound observation is justified by a concrete required guarantee. Revisit scope after audit and split into independently reviewable implementation tickets if necessary; this backlog item is not an authorization to implement immediately.

## Required regressions

1. Real service CLI/IPC with deliberately held worker: inspect current and historical tickets, committed exact execution including saved prompt, service/status and workspace. Inject a slow committed-history query longer than the previous 750ms budget; verify ordinary query completes within its own policy while worker supervision and reset/stop remain responsive. Do not require live proof for immutable report.
2. Concurrent reads spanning atomic control advancement, graph cache misses/hits and repeated same-ID reopen: each result is coherent against its own stated revision, no mixed graph/body/history or cross-cycle evidence. Verify thread-safe bounded cache behavior and no unnecessary owner synchronization.
3. Live worktree changes, ref/worktree cleanup, absent and unprovable local evidence, shutdown and client cancellation, concurrent expensive queries: truthful partial/unavailable results, bounded resources and no worker disruption or read-side mutation. Retain exact cleanup mutation-time revalidation.
4. Exercise all affected read-only endpoints and normal/mutable commands under real contention, including retry/recovery supervision and service startup if observer authority probes are changed. Prove no read-induced authority acquisition interference where passive evidence is sufficient; preserve real exclusive ownership.
5. Measure before/after owner busy time, read latency, Git invocation counts and mutation responsiveness with representative real-sized graph and concurrent requests; identify removed obsolete code/tests. Focused tests, lint, diff check and exact-checkpoint hosted CI for eventual implementation.
