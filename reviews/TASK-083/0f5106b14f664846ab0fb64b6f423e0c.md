## Blocker A — inverted Git ancestry checks (direct code defect)

In `src/devlegate/execution_workspace.py::prepare_rework`:

```python
if not _git(
    self.repo, "merge-base", "--is-ancestor",
    previous_base, previous_checkpoint, check=False
).returncode:
    raise ExecutionWorkspaceConflict(...)
```

`git merge-base --is-ancestor` exits **0 for true ancestor**.
`not result.returncode` is therefore true on the *valid* predecessor
relationship, causing a conflict. An analogous inverted condition exists in
the already-ported branch replay guard
`merge-base --is-ancestor base_head current_head`.

This directly explains the new
`test_rework_ports_linear_multi_commit_delta_and_replays_exactly`
CI failure `previous checkpoint is not descended from its reported base`.
Fix **both** tests of ancestry and distinguish Git status `1` (not an
ancestor) from other Git observation failures (`>=2`), rather than treating
all nonzero results as a normal negative ancestry answer. Include real-Git
true/false/observation-error tests.

## Blocker B — `git cherry` replay proof uses incorrect arguments

Current code calls:

```python
git cherry current_head previous_base previous_checkpoint
```

then assumes its output is exactly `len(delta)` lines of `-`.
However `git cherry <upstream> <head> [<limit>]` enumerates candidates in
`<limit>..<head>`. Here `previous_checkpoint` is a descendant of
`previous_base`, so `previous_checkpoint..previous_base` contains
**no earlier worker commits**. A disposable real Git example with two old
worker commits ported onto a new base produces empty output, not two `-`
lines. The replay check will fail even for an exact previously transplanted
implementation after fixing Blocker A.

Required: prove the exact old series is present without relying on a reversed
`git cherry` range. Validate bounded linear ancestry, no foreign commits,
patch identity and cardinality **in the intended direction**. Test a
successful second call/restart after a multi-commit transplant, tampered
descendant rejection, partial transplant, and an already-integrated old
checkpoint. A plain new-base checkout must never be accepted as completed
when an unintegrated delta remains to port.
