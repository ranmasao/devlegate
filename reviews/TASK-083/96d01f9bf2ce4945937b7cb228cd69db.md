## Blocking issue 2 — crash can silently discard the prior implementation

In `ExecutionWorkspaceManager.prepare_rework()` the current transition is:

1. `retire(previous_worktree)`;
2. CAS `update-ref(work-branch, new_base, previous_checkpoint)`;
3. `prepare(new_base)`;
4. `cherry-pick(previous delta)`.

The replay shortcut says: if current branch != previous checkpoint, invoke
`prepare(new_base)` and accept **any head descended from new_base**.
After a crash or a failed/aborted cherry-pick between steps 2 and 4, the
branch can sit at plain `new_base`. Restart then accepts it as a completed
port and launches the worker **without the previous code**. A foreign but
descendant head can pass the same shortcut.

Required: durable, generation-scoped rework preparation stages or equivalent
fully verifiable Git identity proofs; only accept the exact proven transplanted
head, not arbitrary ancestry. Preserve/recover the original implementation,
stop after a transplant conflict without launching a worker, and never
quietly drop changes. Test SIGKILL/crash or simulated hard interruption at
**each mutation boundary** (after evidence pin, checkout retirement, local CAS,
new checkout, cherry-pick, remote evidence, remote CAS, durable predecessor
write), followed by a restart/second scheduler poll. Prove a single new
execution ID, preserved old code, exact refs and no duplicate cherry-pick.
