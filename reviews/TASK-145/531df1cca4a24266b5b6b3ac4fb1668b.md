## Blocking findings

**P0 — candidate is neither pinned nor durable before destructive effects.** `_build_rework_candidate()` returns only a SHA, removes its temporary worktree, and does not create a persistent candidate ref. `prepare_rework()` then calls `retire()` and `update-ref` before there is any persisted `candidate_head` or transition stage. The old checkpoint has a recovery pin through the service, but restart cannot reliably identify or resume the *verified candidate* and exact swap. A detached candidate commit becomes unreferenced when its temporary worktree is removed, until canonical ref update.

**P0 — crash between retire, CAS and reattachment leaves an unhandled state.** The sequence is still `retire(old)` → `update-ref(old→candidate)` → `self.prepare(base_head)` → owner `_set_rework_preparation_stage("workspace_prepared")` → remote `--force-with-lease`. If interrupted after `retire()` but before `update-ref`, the ticket branch still points to old checkpoint with the canonical worktree missing, and `prepare_rework()` currently raises `previous execution worktree is missing`. If interrupted after CAS but before `prepare()`, branch points to candidate but the worktree is missing. Existing stage `remote_evidence_published` cannot distinguish these states or prove the candidate expected by the interrupted operation. There is no fail-closed, idempotent replay contract for either window.

**P1 — candidate clean-up errors are silently ignored.** In `_build_rework_candidate()` the `finally` block ignores the exit status of `git worktree remove --force`. If removal/registration cleanup fails, `TemporaryDirectory` cleanup can leave unexpected Git worktree registration. Check and surface this condition without mutating the canonical predecessor; avoid masking the primary cherry-pick conflict.

**P1 — no persisted-owner restart/crash or remote-lease race proof.** The new test only proves ordinary cherry-pick conflict. It does not exercise the owner staging and replay at each destructive boundary. Exact-head CI success (if it completes) does not replace these missing tests.
