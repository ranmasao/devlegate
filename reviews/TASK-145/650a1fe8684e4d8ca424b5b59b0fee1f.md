## Single blocking design defect (P0)

`ExecutionWorkspaceManager.prepare_rework()` still does:

```
candidate = _build_rework_candidate(...)  # temporary detached worktree removed
retire(old_workspace, old_checkpoint)      # removes canonical worktree
git update-ref(ticket_branch, candidate, old_checkpoint)
prepare(current_product_base)              # reattach canonical worktree
```

No private ref protects `candidate` before its temporary worktree is removed; no owner-persisted `candidate_head` or swap intent exists before `retire()`. After a crash between `retire`, local CAS, attachment and remote publication, restart cannot distinguish legitimate interrupted progress from a foreign/missing resource. A source checkpoint recovery ref alone is not enough to identify the already verified candidate or avoid a second cherry-pick. The positive scheduler tests (same base, advanced base), transplant conflict preservation and cleanup failure tests do not exercise this defect.

### A. Make candidate creation return a *pinned* identity before temporary worktree removal

In `src/devlegate/execution_workspace.py`, separate candidate generation from canonical worktree/ref installation. Use a private owner-derived ref scoped to the **new execution ID** (e.g. `refs/devlegate/recovery/rework-candidate/<ticket>/<new-execution-id>`). `_build_rework_candidate()` must create the ref **create-only while the detached candidate worktree still exists**, verify its exact target SHA, and only then remove the temporary worktree.
