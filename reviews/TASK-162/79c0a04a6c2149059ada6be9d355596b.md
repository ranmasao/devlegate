   `workspace prune` replace the old public `clean status`.
   `prune` defaults to read-only; `--apply` is explicit, exclusive
   with `--dry-run`. Existing `clean apply` remains for TASK-132
   to replace with one-argument `reset TASK-ID`.
   Table/YAML/JSON and per-resource status/reason are exposed.
2. **Read-only inventory and preview — PASS.** The read-only owner
   command path returns before mutable admission; it makes no durable
   receipt/cursor writes or scheduler/worker launch. A transient
   observer uses Git's no-optional-locks/no-lazy-fetch runner.
   It checks committed vs working control evidence and reports
   incomplete scans rather than silently claiming completeness.
3. **Prune eligibility — PASS.** `completed_only` now requires a
   durably `done` ticket, accepted execution report with independent
   `resource_generation`, matching current ResourceBinding, exact
   integration provenance and published product ancestry. Non-done,
   historical unbound, foreign, dirty, locked or uncertain resources
   are blocked; no resource is adopted based only on a matching path
   or SHA. Automatic cleanup including immediate integration retirement
   has been tightened to preserve missing-generation history.
4. **Destructive execution and replay — PASS.** Explicit apply uses
   the existing serialized `cleanup-workspaces` admission with
   immutable bounded cohort and durable request receipt. Before
   worktree retirement, local ref deletion and remote deletion the
   code repeats ownership, registration, resource and lifecycle
   checks. Local compare-and-delete, recovery of occupied refs,
   remote exact-ref lease, and absent-vs-observation-error semantics
   are retained. Interrupted partial effects have a bounded
   restart path. Reports/reviews/generation evidence are not deleted.
5. **Adversarial regressions — PASS.** New disposable real-Git/owner/IPC
   cases cover done preview/apply/audit preservation, dirty/locked/
   unbound/remote failures, review/todo/backlog/accepted/abandoned
