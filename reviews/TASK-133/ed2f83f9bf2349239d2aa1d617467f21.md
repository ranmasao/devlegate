## Concrete test-design defect, not just missing hardening

`test_pushed_unbound_amendments_reach_scheduler_and_worker` begins by using `git mv kanban/todo/T-1.md kanban/backlog/T-1.md` and committing that move. This is **not a supported workflow edge**: `WORKFLOW_TRANSITIONS["todo"]` permits only `review` or `abandoned`, not `backlog`. The test passes because current ordinary unbound admission consumes the *resulting* valid state and has no general transition-history gate. Thus this proves snapshot delivery but **not** acceptance of an authorized amendment history; it also exposes an actually admitted invalid transition. Replace the backlog positive fixture with an already-backlog ticket (or a legitimate initial creation/bootstrap), keep `backlog → todo` scheduling and separate unbound-todo amendment, and add the corresponding explicit refusal for `todo → backlog`.

## Only remaining essential implementation boundary

The existing `amendment_history.observe_ticket_history()` is only invoked on the **already-bound execution's** control-descendant path. The ordinary unbound path does not establish that the changed ticket was in a legal state for every transition, nor that protected-state edits/deletion/recreation were refused before admitting an unrelated fresh worker. Integrate a narrowly scoped validation at the already serialized owner control-sync/admission boundary, anchored in an existing *durable trusted control head* and verified local/remote head. Reuse `observe_ticket_history()`, the existing ticket-store schema/DAG checks, worker binding, reset/WAL and CAS. Define the bootstrap/previously unobserved boundary explicitly; do not fabricate a baseline or discard errors. The review demands **a single genuine authorization gate**, not a new scheduler, metadata layer or universally repeated full-history sweeps. A malformed or impermissible transition must fail closed before a worker launches; an eligible unbound edit must continue to work.
