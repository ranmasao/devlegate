## Primary acceptance-blocking outcome and next action

In src/devlegate/change_explorer.py, ImmutableExplorer._worktree calls the privileged owner-side Git backend with `git --literal-pathspecs -c core.fsmonitor=false diff-index --raw -z --no-renames --no-ext-diff --no-textconv --ignore-submodules=all <identity> --`. The no-ext-diff/no-textconv switches do not disable Git clean/process conversion filters. A worker-editable .gitattributes can select an already configured local filter; the resulting tool request executes its command in the owner context. This violates the read-only observation / no arbitrary command execution boundary, even without any worker ability to edit Git config or need to implement TASK-152.

Independently reproduced with Git 2.47.3 in a disposable repository: commit a three-byte tracked file containing "aa\n", configure a local clean filter that writes an external marker then copies stdin, add an untracked .gitattributes selecting that filter for the tracked file, change the file to "bb\n", and run the exact diff-index command and environment used by _git (including GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=/dev/null, GIT_ALLOW_PROTOCOL="", GIT_OPTIONAL_LOCKS=0, and the disabled fsmonitor). It reports the changed path and creates the marker. No worker mutation of the private Git configuration is required during observation. An external filter can also outlive a killed Git process, so the bounded Git timeout is not an adequate prevention mechanism.

First add a focused failing regression against the actual Change Explorer WORKTREE query, using a harmless marker-writing configured filter selected by worker-editable attributes. Then prevent external clean/process filter execution at the existing owner Git observation boundary. Prefer the smallest safe solution: reuse existing trusted Git configuration restrictions, neutralize the applicable executable conversion drivers if practical, or explicitly return bounded unavailability for an observation whose conversion behavior cannot safely be disabled. Do not require a new full-tree snapshot, rehash of every file, OS sandbox, generic Git audit, or additional admission protocol. Keep the live editable file semantics; no attempt to prove a perfectly consistent WORKTREE. Preserve applicable core.whitespace and diagnostic attributes for check, not arbitrary executable conversion drivers.
