## Remaining critical blockers

1. **Large worktrees defeat even path inventories.** The new `_worktree()` reads and caches **every non-gitlink tracked and untracked file** up to 16 MiB of aggregate bytes (with a 3-second walk), and `_trees()` scans it twice for each comparison. A single unrelated large file or moderately sized repository makes `changes(BASE,WORKTREE)` fail with `TOO_EXPENSIVE` rather than enumerate affordable changed paths. This violates the canonical requirement that `changes` must not hide changes when file content diff is oversized and the intended bounded selective-reading design. Separate cheap Git/index/path inventory from bounded content sampling; compute/hydrate only what is needed, while maintaining honest stable mutable pagination.
2. **Submodule status is provisional.** For any tracked gitlink, `checkout_status` is always `unknown` and WORKTREE inventories may report a changed/unknown submodule even when no drift is evidenced. Implement bounded factual parent gitlink versus staged pointer and shallow checkout initialized, drift, dirty and unknown states, without descending into nested diffs, fetching, mutating or declaring absent checkout a removed gitlink. The current unknown fallback is not sufficient to finish the acceptance contract.
3. **Incomplete historical reconstruction.** `proven_linear_history` currently requires an exact common base and a first-parent-reachable checkpoint in a bounded chain. Valid retained non-ancestor/rebased/squashed task checkpoints are not represented; a historical report without `resource_generation` must not be globally excluded when independently verifiable via existing Git/report evidence. Preserve fail-closed behavior when actual proof is absent, but do not fabricate or require backfill/migrations.
4. **No durable execution aggregate meter.** Current per-channel `EvidenceSocket` quota exists only in memory and is reset on owner/channel restart. Implement service-owned durable response accounting across reconnect, retries and restart (actual delivered bytes and consistent failure handling), including bounded `revisions` inventories and all tool operations. Keep worker requests read-only.
5. **File/compute edge cases remain.** The 32-KiB whole-file cutoff still refuses large files with cheap small diffs. Bound computation separately from serialized patch output, preserve honest content-type/size/line statistics and page progress, and test changed equal-size binaries, huge lines, type/rename semantics, symlink replacement and verified mutation/stale cursors. New WORKTREE code needs adversarial tests for concurrent writes/removes, mixed index/worktree state, untracked symlink and file-size/scan boundaries.
6. **No actual installed-artifact acceptance.** Current focused tests do not exercise all three TypeScript tools through a real contained OpenCode process; direct Python socket or mocked supervisor is insufficient.
